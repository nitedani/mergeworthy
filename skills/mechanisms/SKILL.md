# Mechanisms

These scripts enforce the rules that failed as text alone. They ship in the mergeworthy plugin: its `bin/` is on the Bash `PATH`, its `hooks/hooks.json` is active while it's enabled, and it updates with the plugin. Change them in the mergeworthy repo, commit and push (1.9); never edit an installed copy. The plugin's options (`badge`, `merge`, `watcher`, `local_model`; `/plugin` → mergeworthy → Configure options) reach the scripts through `~/.mergeworthy/settings.env`, rewritten at every session start; an environment variable `MERGEWORTHY_<KEY>` wins.

| Mechanism | Enforces | How to use it |
|---|---|---|
| `gh-watch-start` | 1.5 | `gh-watch-start <dir> [owner/repo [N]]…`, the one way to start watching; idempotent. Adds `owner/repo N` to `<dir>/threads.txt` (a bare `owner/repo` to `repos.txt`, covering a repo before an issue exists), and starts the daemon under a supervisor: the systemd user service `gh-watch@<dir>` on Linux, a launchd agent on macOS, else a detached daemon that cron revives. Eyes come from `GH_WATCH_EYES`, else `<dir>/eyes`, else your login. It refuses a thread another live watch dir already watches, and prints the Monitor to arm in the session: the session is what answers events, and nothing else wakes it. |
| `watcher/gh-watch.py` (the daemon) | 1.5 | Reports comments, reviews, pushes, merges, closes and CI results to `<dir>/events.log`; adds 👀 within ~10 s for the eyes; reports their 👍/👎 on the agent's comments; prints `### REFACTOR STALE` when a PR's code changed by more than ~80 lines since its last `pr-steps refactor`, and `DEPENDENT of merged …` for `waiting-on.txt`. It records each comment in `replies-owed.md`; it never starts an agent. It runs `tracker-check` when `TRACKER_REPO` is set, and retires itself (service, launchd agent or cron lines included) once every thread is merged or closed and `repos.txt` is empty. State lives in `gh-watch-state.json`, so restarts lose nothing. |
| `tracker-check` | 1.2 | `TRACKER_REPO=o/r TRACKER_ISSUE=N TRACKER_DECISIONS=<comment id> tracker-check`: umbrella checkboxes that disagree with their PR's state, and a Decisions comment last edited before a tracked PR merged or closed. Run it before every report. |
| `post-lint` | 1.6 | `post-lint drafts/x.md --kind reply\|pr\|issue\|inline\|review-record [--repo o/r]`: banned phrases, em dashes, "stacked on", bare `#N`, budgets, unclassified notes, process in the thread, questions without a recommendation, a bare "Done" to a question, deferrals in the notes table, secrets. A reply reads its parent from `drafts/x.parent.md` (`--parent none` when it answers nobody). |
| `gate-pass` | 1.6 | `gate-pass <abs>/drafts/x.md <review output>`: records that `post-lint` passed and the review's final message is exactly `CLEAN` (the draft's sha256 in `<draft>.gate`). A draft that promises work ("I'll", "follow-up PR") first needs a `PROMISED … (<draft name>)` line in `proposals-open.md`. |
| `pre-bash-guard.py` (hook) | 1.6, 1.7, 1.8 | Blocks: a `gh` post or edit whose body isn't a gated draft, or changed since its gate; a post to a repo no running watcher covers; the same gated draft posted twice as new; `gh pr merge` without `--squash --subject "<title> (#N)" --body ""` (with `merge=reviewer`, every merge), and `--delete-branch` while PRs are based on it; `pkill -f`/`killall`; a bare `git stash`; a force-push without a pinned lease; a dev server or e2e run outside `isolated-run`. Use absolute draft paths. |
| `post-bash-register.py` (hook) | 1.5 | Adds a thread you just created to the watch list. |
| `pre-agent-guard.py` (hook) | 1.10 | While the local model is on, blocks a Claude subagent for read-only exploration or a gate review (send it to the local model), unless the prompt has a `NEEDS-CLAUDE: <why>` line; always blocks a Haiku subagent. Inert in a local-model session. |
| `stop-lint.py` (hook) | 1.1.3, 1.5 | Blocks ending a turn with "want me to / should I / your call…" (unless there's a `GENUINE-FORK:` line), after a GitHub post while no live Monitor in the session watches a watcher's `events.log` (a `claude -p` run and a local-model session are exempt: their caller watches), and while any watch dir the session worked in has a reply owed. |
| `session-start` (hook) | always-on | Puts the always-on rules into context, points `~/.mergeworthy/current` at the installed version (the stable path watchers use), and writes `settings.env`. |
| `pr-steps` | 1.7 | `gh pr create` (unless `--draft`) and `gh pr ready` are blocked until HEAD has a `review` and a `refactor` record: `pr-steps review <reviewer output>` and `pr-steps refactor <rating output>` on the final head. |
| `codex-review-model` | `reviewer` | Prints Codex's top-ranked model (premium and older tiers skipped). Exits 3, calling nothing, while Codex's last usage snapshot says out of credits (for 6 h) or rate-limited (until the reset); `--force` skips that check, `--all` lists the fallbacks. |
| `isolated-run` | 1.8 | `isolated-run <command>`: private network and PID namespaces, its own loopback, everything it started killed on exit, outside network through a proxy (`HTTP(S)_PROXY`, `NODE_USE_ENV_PROXY=1`). |
| `claude-swap` | 1.1.13 | Several subscriptions logged in: after `/login` to each, `claude-swap save <name>`; `claude-swap list` shows them. On a usage limit, a `StopFailure` hook running `claude-swap on-limit` (in your own settings, since it's personal) switches every session to the next unlimited account and logs to `~/.claude/profiles/swap-events.log`. |
| `ready-check` (manual) | 1.7 | Before saying "ready", check every item of 1.7's Ready list against the head (`gh pr checks`, the guardian verdict after the last fix round, the body re-read) and paste the result. |
